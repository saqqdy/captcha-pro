### Fixed esbuild version mismatch error
- Error: `Cannot start service: Host version "0.20.2" does not match binary version "0.21.5"`
- Root cause: @dcloudio/vite-plugin-uni had nested esbuild@0.20.2 while root was esbuild@0.21.5
- Fix: Added `pnpm.overrides` in root package.json to force all esbuild to 0.21.5
- After fresh `pnpm install`, nested esbuild was eliminated — override works correctly
- Build now compiles successfully with all 4 pages (index, slider, click, popup)
- Also suppressed Sass legacy-js-api deprecation warnings via vite.config.ts `css.preprocessorOptions.scss`

### Fixed @vue/compiler-sfc type resolution error
- Error: `[@vue/compiler-sfc] Unresolvable type reference or unsupported built-in utility type`
- Root cause: dcloudio's `@vue/compiler-sfc@3.4.21` can't resolve external type imports (`SliderCaptchaProps` from `@captcha-pro/mp-shared`) or built-in utility types (`Omit`) used in `defineProps<T>()`
- Fix: Rewrote all 3 Vue components to use **runtime prop declaration** (object syntax) instead of type-based `defineProps<T>()`
  - `slider-captcha.vue`: `defineProps({ width: { type: Number, default: 650 }, ... })`
  - `click-captcha.vue`: same pattern with runtime props
  - `popup-captcha.vue`: same pattern; `type` prop uses `String as () => 'slider' | 'click'` for TypeScript narrowing
- Types are still exported from `src/types.ts` for consumer TypeScript usage
- Build verified: `pnpm play:uniapp-vue` compiles successfully with no errors, all 4 pages + 3 components + App.wxml generated

### Fixed getCurrentInstance() null error in click-captcha
- Error: `TypeError: Cannot read property '$scope' of null` at `uni.createSelectorQuery().in(instance)`
- Root cause: `getCurrentInstance()` returns null inside event handlers in UniApp — the Vue component context is only available during setup
- Fix: Moved `getCurrentInstance()` call from inside `handleClick` to the setup phase, captured as `const instance = getCurrentInstance()`, then used in `handleClick` via closure

### Fixed click-marker NaN coordinates
- Error: `left:NaNpx;top:NaNpx` on click-marker elements
- Root cause: UniApp WeChat mini-program tap event uses `e.detail.x` / `e.detail.y` (not `clientX` / `clientY` which are web DOM properties)
- Fix: Changed `handleClick` to use `e.detail.x ?? e.detail.clientX` and `e.detail.y ?? e.detail.clientY` — supports both UniApp mini-program (`x/y`) and H5 web (`clientX/clientY`)

## Rewrote packages/uniapp-vue2 based on taro-vue2

### Key adaptation differences from taro-vue2 → uniapp-vue2
- Replaced `Taro.getWindowInfo().screenWidth` → `uni.getSystemInfoSync().screenWidth` (rpxToPx computed)
- Replaced `<View>/<Image>/<Text>` (Taro PascalCase) → `<view>/<image>/<text>` (UniApp lowercase)
- Replaced `Taro.createSelectorQuery()` → `uni.createSelectorQuery().in(this)` (Vue 2 `this` works for selector query)
- Used `<movable-area>/<movable-view>` for slider thumb (same as uniapp-vue3) instead of touchstart/touchmove/touchend on a View
- Used `e.detail.x/y` for click coordinates (same as uniapp-vue3) instead of `clientX/clientY`
- Removed `Taro` import entirely — all APIs now use `uni.*`
- No `Uni` prefix aliases on exports — matches the fix applied to uniapp-vue3

### Component changes
- **slider-captcha.vue**: Rewrote from touch-based drag (View + @touchstart/move/end) to `<movable-area>/<movable-view>` pattern for UniApp compatibility. Added `handleSliderChange` (movable-view @change), `handleSliderDragStart`/`handleSliderEnd`. Same _gs()/_as() pattern from taro-vue2. Uses `loadCaptcha`/`verifySlider`/`resetCaptcha` from mp-shared.
- **click-captcha.vue**: Rewrote from simple e.touches/clientX to UniApp e.detail.x/y coordinate system. Uses `uni.createSelectorQuery().in(this)` (Vue 2 `this` works here unlike Vue 3 which needs getCurrentInstance). Added `clickCharImages` support and `prompt-bar` matching taro-vue2. Uses `verifyClick` from mp-shared.
- **popup-captcha.vue**: Rewrote to match taro-vue2 popup pattern — added `type` prop (slider/click), `maskClosable`, `showClose`, `autoClose`, `closeDelay`, `sliderOptions`, `clickOptions`. Added `show()/hide()/isVisible()` methods for programmatic control. Uses kebab-case `<slider-captcha>/<click-captcha>` component tags.
