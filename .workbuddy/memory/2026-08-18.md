## 深夜补充：修复「切换到非暗黑模式，验证码仍暗黑」

- 根因：`packages/core` 的 CSS 在 `@media (prefers-color-scheme: dark)` 下强制暗色，当用户手动切回浅色并移除 `.cp-dark` 后，媒体查询仍会覆盖为暗色（只要系统处于暗色模式）。
- 修复：在 `packages/core/src/utils.ts`、`packages/core/src/popup.ts`、`packages/core/src/styles/index.css` 中新增 `.cp-light` 显式浅色覆盖规则，并置于媒体查询之后，确保手动浅色优先级高于系统暗色。
- 同步更新所有 examples 的切换逻辑：Vue/Vue2/React/HTML 的 Header 在切浅色时给 `html` 添加 `.cp-light`、移除 `.cp-dark`；taro-vue/taro-vue2/taro-react/uniapp-vue/weixin 首页根节点在切浅色时添加 `.cp-light`。
- 验证：`pnpm build:core`、`pnpm turbo build`、`pnpm turbo test` 全部通过。

## 深夜补充：修复 `pnpm play:vue2` 版本不匹配

- 问题：`pnpm play:vue2` 报错 `Vue packages version mismatch: vue@3.5.41 (root) vs vue-template-compiler@2.7.16`。
- 根因：根目录 `.npmrc` 使用 `node-linker=hoisted`，把 `vue@3` 提升到根目录 `node_modules/vue`；`vite-plugin-vue2` 加载的 `vue-template-compiler` 在运行 `require('vue')` 时命中了根目录的 `vue@3`。
- 修复：参考 `packages/vue2/build/preload-vue2.cjs`，在 `examples/vue2/build/preload-vue2.cjs` 复制同一份预加载脚本，并在 `examples/vue2/package.json` 的 `dev` 脚本中加入 `NODE_OPTIONS='-r ./build/preload-vue2.cjs'`，让 Node 在启动 vite 前把 `require.cache` 中 `vue` 的解析路径指向本地 `vue@2.7.16`。
- 验证：`pnpm play:vue2` 正常启动，`pnpm --filter example-vue2 build` 正常构建。

## 补充：修复 `examples/html` 开启暗色后验证码不变暗

- 问题：`examples/html/index.html` 切到暗色模式后，页面 UI 变暗但验证码组件没有暗色效果。
- 根因：HTML 示例原来引用的是 unpkg 远程 CDN：`https://unpkg.com/captcha-pro/dist/index.global.min.js`，该远程版本还没有 2.3.0 的暗色模式 CSS 变量逻辑。
- 修复：
  - 把脚本改为加载本地构建 `core-dist/index.global.js`。
  - 在 `examples/html/core-dist` 创建指向 `../../packages/core/dist` 的 symlink，使本地静态服务器和直接打开文件都能访问到最新构建。
- 验证：通过 `python3 -m http.server` 启动本地服务器，确认页面引用的是 `@captcha-pro/core v2.3.0` 且 JS 可正常加载。

## 补充：修复暗色模式下初始状态 slider track 文字/按钮/刷新按钮无样式

- 问题：暗黑模式下初始状态，`captcha-slider-track` 文字仍黑色、`captcha-slider-btn` 无背景色、刷新按钮无背景色。
- 根因（HTML 示例）：`examples/html/index.html` 只加载了 `core-dist/index.global.js`，而该全局 IIFE 构建不会自动内联完整 CSS，只注入少量运行时样式；暗色变量未生效。
- 根因（Vue/Vue2 wrapper）：`packages/vue/build/vite.config.ts` 与 `packages/vue2/build/vite.config.ts` 的 `copyCoreCss` 插件在 `buildStart` 阶段把 core 的 `index.css` 复制到 `dist/style.css`，但 Vite lib mode 在构建结束时会用收集到的 scoped CSS 覆盖 `dist/style.css`，导致最终只包含 Vue 组件的 scoped 样式（约 200~300 字节），丢失了 core 暗色变量。
- 修复：
  - HTML 示例在 `<head>` 中增加 `<link rel="stylesheet" href="core-dist/style.css">`，与 `core-dist/index.global.js` 一起加载。
  - 将 `packages/vue`、`packages/vue2`、`packages/react` 的 `copyCoreCss` 插件从 `buildStart` 改为 `writeBundle`，确保在 Vite 写完所有资源后再把 core 的完整 `index.css` 复制为 `dist/style.css`。
  - 在 `examples/html/index.html` 的 `init()` 中增加 `?theme=dark` URL 参数支持，便于 headless 验证。
- 全面排查其他子项目：
  - **已修复**：`packages/core`、`packages/vue`、`packages/vue2`、`packages/react`、`examples/html`、`examples/vue`、`examples/vue2`、`examples/react`。
  - **存在不同层级问题**：小程序相关包（`packages/taro-vue`、`packages/taro-vue2`、`packages/taro-react`、`packages/uniapp-vue`、`packages/weixin`）的 SCSS/WXSS 使用硬编码颜色，只通过 `@media (prefers-color-scheme: dark)` 跟随系统主题，没有 `.cp-dark` 类覆盖；因此 examples 中的手动暗色开关对这些包内的验证码组件样式不生效。
  - **建议**：若需要小程序示例的手动开关真正控制验证码暗色，需要把这些包的 SCSS/WXSS 也改为 CSS 变量或增加 `.cp-dark` 覆盖规则。
- 验证：
  - 用 Chrome headless 截图验证 `examples/html` 与 `examples/vue` production build 在暗色模式下，slider track 文字、slider button、refresh button 均正确显示暗色样式。
